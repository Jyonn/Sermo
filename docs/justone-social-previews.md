# Social media previews

Douyin and RedNote use JustOneAPI exclusively. Configure `JUSTONEAPI_TOKEN` in a protected server environment file. Never expose it to Vite, client DTOs, logs, or repository files. Requests use the official SDK's HTTP contracts: share-url-transfer/v1, Douyin get-video-detail/v2, RedNote get-note-detail/v1. No HTML/feed scraping fallback remains.

An account with permanent VIP has 7 shared Douyin/RedNote parsing attempts per China-time calendar week (Monday 00:00). An attempt covers short-link expansion plus detail retrieval. Failed upstream attempts count; missing configuration and permission denials do not. Message sending/statement publication schedule the first uncached resolution under the sender. Repeated sends of an existing cached link are free. Reads and composer previews never start paid work. Later resolutions require authenticated POST refresh with both `force:true` and `confirmed:true`, charged to that requester. Usage is durable; a locked user row serializes quota updates across both platforms and workers.

Metadata is retained indefinitely. Neither a 15-minute TTL nor guesses about upstream `t` parameters invalidate it. Opening a cached card shows its Drawer without resolution. Playback tries the cached URL first; a missing/failed stream prompts for one paid resolution. Only ordinary link bubbles without metadata have a right-side Resolve action, so another eligible VIP can resolve the shared link. Cached cards never show this external button. Failed refreshes preserve previous metadata and cover. Platform locks coalesce concurrent refreshes. A short-lived `social_parsing` marker supports cross-worker read-only polling and expires only as UI state, never as an automatic paid retry.

On paid resolution, an allowlisted cover URL is downloaded without redirects (3 MiB and 16 megapixel bounds), stripped/re-encoded to a 960px WebP, and saved under its content hash in `frienden/social-covers/` in the existing private Qiniu bucket. Only the stable key is stored; serialization signs a fresh download URL. Failed thumbnail copies retain the upstream cover and never trigger another parse. Existing cached metadata is not silently re-parsed to backfill a cover.

The RedNote v1 response tested on 2026-11-18 exposes some video notes without a video stream. Their metadata is retained, with explicit resolution/source fallback; a cover is never classified as a gallery or native audio used as video. Live Photo still images are usable; live motion playback is not added by this change. RedNote CDN hosts are allowed explicitly.
